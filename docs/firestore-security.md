# Firestore 보안 규칙

`firestore.rules`가 규칙 원본이며 `firebase.json`에서 연결합니다. 로컬 파일 작성은 원격 배포가 아닙니다.

| 경로 | 읽기 | 쓰기 |
| --- | --- | --- |
| `users/{uid}` | 본인만 (이메일 포함) | 본인 생성·수정, 직접 삭제 금지 |
| `users/{uid}/links/{id}` | 누구나 | 로그인한 본인만 생성·수정·삭제 |
| `users/{uid}/linkClicks/{id}` | 단건 조회 공개, 목록 조회 본인만 | 누구나 최초 1 생성·정확히 1 증가, 삭제 본인만 |
| `users/{uid}/profile/{id}` | 누구나 | 로그인한 본인만, 공개 프로필 필드만 |
| `publicProfiles/{uid}` | 누구나 | 로그인한 본인만, 공개 프로필 필드만 |
| `displayNames/{name}` | 단건 조회만 공개 | 본인 이름 예약 트랜잭션만 |
| 그 외 | 거부 | 거부 |

`users/{uid}/profile`은 컬렉션 경로이므로 문서 ID가 필요합니다. 현재 앱은 비공개 `users/{uid}`와 공개 `publicProfiles/{uid}`를 사용합니다. 공개 필드는 이름·사진·소개이며, 이메일은 공개 문서에 저장할 수 없습니다. 공개 프로필 값은 같은 트랜잭션의 사용자 문서와 일치해야 합니다.

추가 보호:

- 클릭수는 링크 문서가 아닌 `users/{uid}/linkClicks/{linkId}`의 `clickCount`에 저장합니다. 실제 링크가 있어야 하며 허용된 유일한 필드는 정수 `clickCount`입니다. 링크 삭제 시 클릭수 문서도 배치로 함께 삭제합니다. 공개 단건 조회는 클릭수 트랜잭션에 필요하며, 공개 페이지에서 수치를 숨기는 것은 비밀 데이터 접근 통제가 아닙니다. 반복 요청을 통한 수치 부풀리기는 방지하지 못합니다.

- 링크의 필드·자료형·길이·URL 프로토콜·아이콘을 검사합니다.
- `createdAt`은 생성 시 서버 시간이며 이후 변경할 수 없습니다. 수정 시 `updatedAt`은 서버 시간이어야 합니다.
- 표시 이름은 2~20자이며 대소문자를 구분하지 않습니다. 이름 예약과 사용자 문서의 `displayNameKey`를 `getAfter`로 함께 확인하여 다른 사용자의 예약 탈취를 차단합니다.
- 계정 삭제는 하위 링크·공개 프로필·이름 예약의 정리가 필요하므로 클라이언트의 사용자 문서 단독 삭제를 차단합니다. 계정 삭제 기능 구현 시 신뢰할 수 있는 서버에서 일괄 정리해야 합니다.
- 이미지 업로드를 추가한다면 Firebase Storage 규칙에서 별도로 소유권·파일 크기·콘텐츠 유형을 검사해야 합니다. Firestore 규칙은 Storage나 Admin SDK를 제어하지 않습니다.
- App Check와 사용량 모니터링은 공개 읽기의 남용을 줄이기 위한 별도 운영 설정입니다. 공개 링크·프로필 목록은 누구나 조회할 수 있으며 비밀 정보를 넣으면 안 됩니다.

## 배포 전 검증

에뮬레이터에서 비로그인 공개 읽기 허용, 비로그인·타인 쓰기 거부, 본인 CRUD 허용, 잘못된 필드·시간·이름 예약·공개 이메일 거부를 확인해야 합니다. 현재 환경에 Java가 없어 Firestore Emulator 실행 및 규칙 실행 검증은 수행하지 못했습니다. 앱의 타입 검사나 서비스 단위 테스트가 규칙 검증을 대체하지 않습니다.

검증 후 명시적으로 배포할 때: `firebase deploy --only firestore:rules --project my-hi-link`. 기존 원격 규칙의 다른 경로가 필요한지도 먼저 확인합니다.
